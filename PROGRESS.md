- [x] F2.7 Worker: cron, night lock, runUser pipeline *(2 commits)* — `feat(worker): add scheduler and night lock` / `feat(worker): add per-user night pipeline`
  - `runUser` decrypts the management key in memory, caps an ephemeral key from the live balance (iAI uses `credit_balance` minus the safety margin and never the deposit; budget mode may also spend the deposit, up to the nightly cap) and runs the optimizer plus the three executors. Outputs go to the real storage client; request ids, traces and reported cost are stored on the task. The key is revoked before the function returns. A 0G balance is converted with the median rate implied by the live catalog's `pricing` (wei) and `pricing_usd`; if the catalog has no such pair the user is marked failed and no key is created. Commons (F4) and Merkle leaves (F3.8) are not in this step: leftover budget is logged and not spent, and leaves will be built from the stored steps. If a reported cost exceeds its estimate by more than 20%, the rest of that user's night is replanned (plan §8.3). Anchoring stays in F3.9.
- [x] F2.8 Key sweeper — `feat(worker): add ephemeral key sweeper`
  - Every 10 minutes, and once at process start, the worker revokes `NightRun` keys that are still alive and at least 2 hours old. It decrypts that user's management key in memory and calls `sweepOrphanedKeys`; `keyRevokedAt` is set only after the Router revoke succeeds, so a failure is retried next sweep. On start, `RUNNING` tasks with no Router request id in `steps` go back to `QUEUED`. Tasks that already recorded a request id stay `RUNNING`. The 10-minute sweep does not requeue: a live batch marks a task `RUNNING` before the request id exists.
- [x] F2.9 Run-now endpoint using the real pipeline *(2 commits)* — `refactor(core): share the night pipeline with the web app` / `feat(web): add run now endpoint`
  - `POST /api/runs/now` requires a session and calls the same `runUser` as the worker (moved to `packages/core` so the web app does not keep a second pipeline). Manual `Night.id` is unix seconds (`manualNightId`): the column is a BigInt, so the plan's `manual-<timestamp>` string does not fit. The 10-minute limit applies to pipeline starts; a missing key, an empty queue, or a missing storage signer fails first and does not call the Router. `OPERATOR_PRIVATE_KEY` is read only to build that route's storage client and stays off `WebConfig`. Anchoring a manual batch stays in F3.9, same as the nightly `runUser`.
- [x] F2.10 Unit tests: vault, executors' parsing, redaction — `test(core): cover vault, executors and log redaction`
  - Vault tests from F1.5 already covered the round-trip, a wrong key, tampered ciphertext/tag/iv and account binding. Added the reverse context check (a seal with no account must not open under one), truncated iv/tag, and a check that every failure — including a bad master key — omits the secret. `openSecret` now rejects an auth tag that is not 16 bytes: Node's GCM accepts a 4–16 byte tag, so a truncated copy of a real tag used to decrypt. Executor tests inject Router-like bodies (verbose transcription, chat completions, image `b64_json`) and partial ones (missing `text` / `choices` / `message`, url-only images, schema mismatches) with no live calls. A partial chat body is now an `ExecutorOutputError`: `chatText` used to throw `TypeError` when `choices` or `message` was absent. Logs go through `redact` / `redactString` (pino is not wired): `mk-` / `sk-` tokens are stripped from nested fields and error strings, and `authorization` values are replaced. Tokens with fewer than 6 characters after the prefix are not treated as secrets. The Phase 0 spike still has its own copy of the helper in `scripts/lib/redact.ts`.

- [x] F3.2 Cost estimator — `feat(core): complete cost estimator`
  - Chat, audio and image estimates (×1.15, atto→micro ceil) were already in `packages/core/src/catalog/estimator.ts` and exported from `@shift/core`; the optimizer already calls `estimateCostMicro`. This commit adds `estimateDecisionMicro` for the complexity call (input tokens × catalog prompt price, same padding and ceil), rejects a model of the wrong kind, and clamps non-finite sizes so a bad length cannot estimate a negative cost. Transcription still treats `pricing_usd.prompt` as USD per second (the Router does not document the unit). Image cost is the flat per-image price plus the refine chat the executor runs; if the image model bills input tokens, those are the planned revised prompt. z-image-turbo has no size-tier variants, so `pricing_usd.variants` is not read. The file stays next to the catalog it prices (STRUCTURE.md lists an `optimizer/` estimator). Planning only: the Router's reported cost is still the real one. No credit spend.
- [x] F3.3 Complexity classification with decision models — `feat(core): classify task complexity with decision models`
  - `buildComplexityRequest`, `readComplexity` (confidence below 0.5 plans `standard`), `classifyComplexity` (one real `/v1/decisions` call; a failed call plans `standard` and does not fail the task) and `MIN_QUALITY` (simple 1, standard 2, complex 3) were already in `packages/core/src/optimizer/complexity.ts` and exported from `@shift/core`. This commit adds `pickDecisionModel` and `classificationSpendMicro`. The picker reads ids only from the catalog: the strictest trust tier that has a decision model (private TeeML, then verified, then standard), then the smallest `contextLength` that can hold the task text (Laya's 512 tokens when the text fits, otherwise a larger context such as Vela), else the largest context in that tier. No decision model at all plans `standard` and does not call the Router, so an empty TeeML catalog spends nothing. `runUser` subtracts the step's reported cost from the night budget, or `estimateDecisionMicro` of the state actually sent when the response carries no cost. Tests inject `decide`. No credit spend.
- [x] F3.4 Budget optimizer (base + greedy upgrades) — `feat(core): add budget optimizer`
  - `optionsFor` and `planNight` were already in `packages/core/src/optimizer/optimizer.ts` and exported from `@shift/core`. This commit locks plan §10.4 with synthetic catalogs (no Router calls): the quality frontier, a cheap base by priority then `createdAt`, greedy upgrades by (Δquality × priority) / Δcost, same-price quality kept as the base, and `remainingMicro` left untouched for commons. Empty catalog, zero and negative budget, `no_model` vs `over_budget`, and a minimum quality the budget cannot buy are covered. `runUser` already writes `MIN_QUALITY` from F3.3 onto each text task before the execution `planNight`; the pre-key preview stays at floor 1 because classification needs the ephemeral key. - [x] F3.5 Adaptive replanning during execution — `feat(core): replan when real cost drifts`
  - `runUser` already replanned after a successful task when the reported cost was above 1.2× the estimate (or any positive cost on a zero estimate), and already removed the failed model on `exclude_model_and_replan` / `switch_provider_or_model` before planning again.
